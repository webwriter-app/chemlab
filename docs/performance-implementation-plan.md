# ChemLab performance review and implementation plan

Reviewed at `c10aefc` on `perf/echem-startup`. This plan covers the lab runtime, chemistry, charts, asset loading and resource lifetime. It builds on the completed SMILES batching and loading indicator. The periodic table notes cover the separate committed `main` snapshot `1e26f1a`, including the condition and discovery modes.

## Findings and priorities

| Priority | Area | Evidence from the current code |
| --- | --- | --- |
| 1 | Canvas invalidation and input | Raw pointer coordinates trigger Lit updates. Each canvas repaint revisits immersed-device ordering and all cables, including during pure pan and zoom. Resize can draw twice. |
| 1 | Chemistry per simulation step | Ionic resistance, electrode candidate selection and open panels can independently solve the same aqueous state. Within one vessel view, the same proton balance is already solved twice. |
| 1 | Charts and long sessions | A data change can rejoin and copy the history of every visible chart. Trimming an axis repeats that work even when its data is unchanged. |
| 2 | Palette and vessel inspector | The components drawer is rendered even when closed. The chemical catalog is deferred until first opened but keeps building/filtering its cards once initialized, including while hidden. A live inspector updates separately from the recorder. |
| 2 | Cold startup and rendering resources | The lab JS asset is 9.36 MB raw, 1.82 MB when gzipped locally. All component textures are awaited before Pixi can mount. Detached widgets stop the ticker but retain the renderer and its event bindings. |
| Profile first | General persistence and periodic table | Author writes can be reparsed by the widget's own observer. The periodic table now repeats matching, cell rendering and print preparation during its condition and discovery slider updates. Trace that interaction separately from ChemLab canvas work. |

### What was measured

- **Chart data preparation.** A Node benchmark used the real `MeasurementHistory` and `diagramData`, four retained time/value pairs with independent smoothly varying 10 Hz readings and one prune per simulated second. Across 32 reads after warmup, preparing all four datasets took **1.6 ms median / 3.5 ms p95** at five minutes (3,000 points per chart), **4.0 / 5.5 ms** at one hour (about 9,660 per chart), and **21.0 / 35.2 ms** at four hours (about 31,430 per chart). The run excluded Chart.js rendering, event dispatch and browser layout.
- **Chemistry.** An instrumented Node run counted **12 proton solves per evolving bridged Daniell step** and about **62 per step** for the tested same-vessel graphite/NaCl electrolysis (1 M NaCl, 10 V, 0.5 A limit). Reading pH, species and saturation in sequence on an unchanged CuSO₄/ammonia bath called the proton solver three times. These counts characterize the tested scenarios.
- **Canvas.** The echem snippet has 31 vessels and 84 saved electrical entries, before synthesized cables. The current stacking pass visits at least **2,604 vessel/device combinations** per rendered frame for this layout. This is a code-derived operation count. Browser frame cost has yet to be measured.

## 1. Keep pointer and canvas work local

**Paths.** [Canvas events and scene updates](../controllers/CanvasController.ts#L1307), [frame flush](../controllers/CanvasController.ts#L1380), [dipped stacking](../controllers/CanvasController.ts#L1537), [cable update](../controllers/CanvasController.ts#L1592), [host updates](../webwriter-chemlab.ts#L697), [simulation ticker](../controllers/SimulationController.ts#L30).

1. Make raw pointer coordinates nonreactive and keep their existing world-coordinate meaning. Pointer HUD, selection geometry and previews should request an update only when their visible output changes. Explicitly request a Pixi repaint when a port hover begins or ends. For active drag, consume the latest motion once per frame where it is safe, and apply the final position synchronously on pointer release. Preserve Alt-click, additive marquee, pointer identity, cancel, pinch, and timed transfer holds. If traces show Pixi global pointer traversal is significant, enable global movement only while a gesture requires it and verify release/cancel outside the canvas.
2. Split scene dirtiness into changed vessel visuals, changed attachment/stacking, and dirty or awake cables. Index the attachment relationship by mixture and the incident leads by device. Update those relationships through attach/detach, restore, removal and rewiring. Re-evaluate electrode wetting when a vessel's surface changes and track both candidate vessels for a dry bridge so it can become conductive when filled. Reorder only when membership or layer order changes. Step awake leads and use stored geometry for settled leads. Determine cable ordering when scene membership changes.
3. In restore, place and update vessel views before attaching devices. Resolve cable endpoints from their terminals and saved free-end offsets before first paint. Seed loaded leads with a settled sag using their span and length, preserving the interaction's rope dynamics after dragging or rewiring. Remove the duplicate initial fill/attachment pass once first-frame parity is verified.
4. Coalesce resize to one backing-store resize, camera fit and paint per applied size/DPR. Apply the camera before drawing. Keep the existing auto-fit behavior on drawer animations and viewport changes. Try cheap collision fixes first, including unchanged snapped-position checks and cached world-space footprints. If dense traces still show repeated full scans in [collision and free placement](../controllers/CanvasController.ts#L240), add a world-space broad phase with exact existing overlap exceptions and z-order as the final test.
5. Share the upright liquid-surface calculation between fill rendering, electrode wetting and transfer effects. Hoist constant surface checks out of particle loops. Coalesce repeated fill or particle redraws within one frame after measuring [VesselView](../controllers/VesselView.ts#L200). Keep tilted-volume geometry and liquid-phase separation covered.

**Acceptance.** A stationary pointer and empty-canvas hover produce zero unrelated Lit updates. Warmed pure pan/zoom performs zero attachment/order recomputations and zero settled-cable integration. A moved terminal updates its incident leads, including, where applicable, both ends on the same device. Check legacy and explicit cables, open ends, detachment/undo, overlapping electrodes and bridges, same-vessel and different-vessel geometry, mixed phase fills, sediments and gas effects. Verify existing workspace-camera tests and manually repeat mouse, touch and resize in WebWriter. Split input and scene changes into separate commits.

## 2. Reuse chemistry results within a known mixture state

**Paths.** [Salt ion view](../chemlib/Simulation.ts#L718), [aqueous vessel view](../chemlib/Simulation.ts#L1080), [ionic resistance](../chemlib/Simulation.ts#L2475), [echem step](../chemlib/Simulation.ts#L2736), [speciation readout](../chemlib/Simulation.ts#L3285), [recorder](../controllers/MeasurementRecorder.ts#L109), [selected-object popup](../webwriter-chemlab.ts#L2186).

1. Extract a private read-only equilibrium result containing composition, free proton concentration, water constant and complex-speciation results for a known bath state. Pass it into the ion and vessel views so the view and its ion list share the same solve. Keep writable ion handles associated with the active calculation. Reuse the resulting bath view for conductivity and electrode candidates within one electrochemical step, and build only one for a shared bath. Start with one operation-scoped map keyed by mixture identity and preserve the order of all bookings and settling.
2. After a state-changing step, build a fresh snapshot for the recorder and selected inspector. Where saturation and species presentation can share the result, pass it explicitly. Keep full precision for physics and round only for display. Temperature, volume, amount, dissolved gases, electrode/excess charge, hypochlorite and other inputs can invalidate a result. Add a persistent revision cache only after auditing mutation boundaries and proving invalidation. Use no cached pre-step equilibrium across extent application, precipitation, transfer, solvation or temperature changes.
3. Profile chloralkali separately. The [chlorine equilibrium residual](../chemlib/Simulation.ts#L2869) performs a proton solve at each candidate extent and may run repeatedly during settling. Reuse invariant inputs first. If still dominant, test whether a root can be bracketed entirely inside the existing no-mutation tolerance before skipping a solve. Retain the full bounded path whenever that condition is inconclusive. Validate the residual, forward and reverse directions and conservation under extremes before considering a solver change.
4. Keep the simulation step and sample timeline fixed. Optimize graph/ion construction within additional hot paths only when profiling shows cost. The completed batching work supplies a reusable pattern for graph construction.

**Acceptance.** Lower proton-solve counts in bridged and shared-bath tests. Compare per-step pH/speciation, partial currents, terminal readings, charge and material balances, gas, salt precipitation and plating with the baseline at existing tolerances. Include strong/weak acid titration, mixed ligands, reversible chlorine, surface displacement and RC without a bridge. Run the existing chemistry suite and add focused tests for lifetime and invalidation only where the optimized code introduces a new boundary.

### Follow-ups if chemistry still dominates

- **Proton and complex residuals.** Build a conjugate lookup once from stable acid-family data. Prepare Ka values once per solve and accumulate mean charge directly for root evaluations. Allocate full fraction arrays when species are needed. In the ligand solver, hoist the free-metal bound for each fixed H out of the inner ligand search. Compare numerical residuals and convergence on near-neutral, concentrated, weak, polyprotic and competitive complex baths before changing any tolerance. [Acid-family inputs](../chemlib/Simulation.ts#L3415) · [Charge solver](../chemlib/AcidBase.ts#L95) · [Complex solver](../chemlib/complexes.ts#L52)
- **Circuit solve.** Replace repeated array membership checks with order-preserving set lookups. Trace network topology and dense stamping separately. If significant, share terminal topology and row indices for a known wiring/meter-mode revision. Reuse matrix factorization only for identical coefficients and changed right-hand sides. Ionic resistance, source/current limits, references and solution conditions can change those coefficients. Verify parallel leads, direct supply-to-meter, reference electrodes, current limiting, disconnect/reconnect and RC transitions before shipping. [Reachability](../chemlib/ComponentManager.ts#L113) · [Matrix preparation and solve](../chemlib/circuit.ts#L132)
- **Volume-limited dosing.** The fit search can re-scan all mixture constituents 38 times. Prepare an exact composition descriptor for each of the two mixtures per call. Try a direct result for additive volume and retain bounded search over the prepared inputs for nonideal contraction. Verify the zero-dose boundary, tiny fractions, solutes and solids, immiscible liquids, full vessels and mass conservation. [Volume fitting](../chemlib/Mixture.ts#L207)

## 3. Update only charts whose data or view changed

**Paths.** [Chart invalidation](../controllers/DiagramController.ts#L63), [draw loop](../controllers/DiagramController.ts#L435), [sample writes and RC segments](../data/measurementHistory.ts#L102), [archive and join](../data/measurementHistory.ts#L158), [range projection](../data/diagramRanges.ts#L38).

1. Add data revisions keyed by channel and archive pair. An appended sample, changed value at the same timestamp, gap or retirement, relevant analytic RC expansion, and prune affecting the pair must invalidate the data view. Keep the channel catalog version separate. Use existing pair reference counts to release caches. Separate data, range, visibility, size and style dirtiness in the controller. A trim or resize should reuse the joined points, base ranges and titration markers. An event on an unrelated series should leave the visible chart alone.
2. Cache the ordered joined series and the shared calculations for identical pairs. Keep the time-origin and axis-swap rules explicit in the display cache. Begin with full rebuild on relevant changes. If long running series still dominate, incrementally append the recent suffix, retaining enough boundary state for held values, last-timestamp replacement and analytic overlays. Force a rebuild when the affected prefix cannot be updated safely.
3. After measuring actual Chart.js cost, add an optional pixel-width projection for large traces. Form buckets within contiguous finite segments in chronological order. Preserve gap boundaries, extrema and entry/exit points. Time charts can group by screen X where ordered. For nonmonotone X, use chronological chunks or keep the full view until a safe projection is tested. Use full series ranges for autoscale and exact data for zoom and titration marker calculation. Keep analytic RC detail within its short interval and verify it remains visible. Start with render-only projection. Preserve the five-minute raw retention, archived-pair lifetime and historical readings.
4. Separate data recording from topology invalidation. Refresh diagram suggestions when a run starts or source eligibility changes. Retain dismissed suggestions until their components leave. Index gas collectors by attached mixture if the per-record lookup is significant. Batch retirement of large multi-selections if profiling the removal path shows repeated channel scans.

**Acceptance.** Unrelated samples cause zero updates to the chart. Dragging a trim handle causes zero joins and marker recalculations for immutable data. Repeated/reversed pairs agree with baseline across expiry, gaps, same-time replacements, first-titration-dose offset and RC. Check reopened offscreen charts, and sample CPU and heap after the four-hour synthetic workload. If archive memory itself remains an issue, measure it separately and agree a retention policy before changing how long archived data remains available.

## 4. Limit palette and inspector updates to visible work

**Paths.** [Drawer visibility and tabs](../webwriter-chemlab.ts#L3475), [catalog grouping](../webwriter-chemlab.ts#L3737), [amount formatting](../webwriter-chemlab.ts#L1908), [vessel carousel and lookup](../webwriter-chemlab.ts#L2104), [molecule lookup](../chemlib/StructureManager.ts#L711).

1. Build and update the active drawer content only when its dependencies change. Keep tab selection, search, scroll and concentration controls in stable instance state. Cache localized search tokens by catalog and locale, and permission summaries by permissions and author/learner mode. Leave concentration recipe construction to selection or drag start. Reuse number formatters by locale and precision. Keep pre-generated images. Try section-level or keyed-item reuse before introducing virtualization.
2. Feed the inspector the exact post-step snapshot from batch 2. Distinguish values changing from species identity or chart status changing. Keep the selected carousel slide and existing nodes when values alone change. Generate thumbnails for the active and nearby slides first if visual and keyboard checks pass. Scope reusable image data by complete molecule representation and drawer settings. Keep unique DOM nodes for distinct slides.
3. Deduplicate in-flight optional compound-name lookup by exact SMILES and keep a bounded result cache. The present helper stores a fetch-success flag on the class, so one request can change state read by another. Return outcome per request and apply results to the matching view only. Keep the local formula available immediately and survive offline or failed requests. Treat lookup work separately from the chemistry step.
4. Authoring low priority. Compare the raw saved data-block text before reparsing it in the mutation observer. Skip self-authored identical snapshots. Preserve legacy attribute reads, explicit author actions, undo/redo, remote replacements and escaping of script data. Batch a multi-object edit into a single save where the existing transaction allows it. Leave routine per-edit serialization alone unless larger-worksheet traces show it contributes.

**Acceptance.** Selection-independent canvas activity causes no hidden catalog rebuild. Search, author permissions, concentration presets, drag/drop, scroll position and focus remain consistent when switching tabs. A live selected vessel updates values without recreating unrelated carousel slides. Verify clipped menus, read-only mode, preserved offline names and behavior with more than one widget.

## 5. Reduce first-load bytes and manage released resources

**Paths.** [Entry imports and eager drawer initialization](../webwriter-chemlab.ts#L14), [component texture preload](../controllers/CanvasController.ts#L1260), [texture table](../data/componentGraphics.ts#L279), [localization loader](../localization/localization.ts), [disconnect](../controllers/CanvasController.ts#L722), [widget exports](../package.json#L151).

1. Load only unique textures required by the current authored scene. Include variant graphics and fallback art where needed and exclude procedural cables from the critical list. Create the renderer and request known textures concurrently where safe. A palette item should wait for its texture or use an intentional preview fallback on first placement. Keep Pixi's texture cache and mipmap/zoom behavior. Protect auto-start and progress against stale loads, failures and disconnect. Validate blank, legacy and new snippets.
2. Collect the actual production build's module sizes and browser evaluation time. A marker-based estimate of the existing bundle attributes about 3.37 MB to Kekulé, 1.81 MB to localization-related sections, 1.75 MB to Pixi, 0.43 MB to Chart.js and 0.41 MB to SmilesDrawer before compression. These estimates locate candidates in the bundled file. Start by removing constructor-time work and deferring charts and drawing code until a real first use. Use selective Chart.js registration if required surfaces and plugins can be enumerated and tested. The locally cached WebWriter build CLI bundles dependencies by default for WebWriter 1 and enables shared chunks under `--shared-dependencies` for WebWriter 2. Run a packaging spike before enabling that mode. Confirm which editor and export modes can resolve generated chunk paths and whether dynamic imports defer bytes, evaluation, or both. Measure whether locale chunks preserve all 111 current locale entries, regional fallback, live language changes and offline export.
3. Treat Kekulé as a longer-term optimization. It is used by the core molecule model and solvation before any inspector opens. First test whether the installed package can expose a smaller supported set while retaining graph/SMILES facilities and fallback rendering. Moving all Kekulé behind an inspector would require separating simulation data from display-time graph handling. Consider that only after collecting a profile and chemistry parity evidence.
4. On detach, stop input routing and observers along with the existing ticker stop. Verify the installed Pixi renderer's event detach/rebind path on WebWriter reparent and undo. Track in-flight startup and input tasks so obsolete work cannot continue on a removed widget. Measure retained renderer contexts, per-widget generated scale textures, charts, canvases and JS references. Assign ownership for final disposal and keep shared textures available to surviving widgets. Prototype deliberate renderer recreation only if transient moves and permanent deletion can be distinguished safely or the interaction state can be restored.

**Acceptance.** A cold blank lab doesn't await a full model-independent catalog of textures. Compare raw and compressed artifact size and actual executed code on first use, then verify local import and offline/export loading of every required asset. On detach, no renderer input callbacks should reach that widget. After repeated insert/remove cycles, retained resources should return to the level for the currently connected widgets. Check that reconnect preserves a selected view, live history and other worksheet instances.

## 6. Periodic table follow-up after integration

The table already builds localized search tokens once per module and ships its own widget entry. Its checked-in JS grew from **471 KB to 586 KB raw** between `c96819a` and `1e26f1a`. The new sliders call `requestUpdate()` on each valid slider input. The render rebuilds the match set, computes each grid cell's mode and label, and runs both screen and print detail rendering. The phase model uses direct arithmetic over 118 elements. Measure preparation and DOM cost separately before optimizing the model. The code references below use `git show 1e26f1a:<path>`.

1. Profile temperature, pressure and discovery scrubbing in one table and in a worksheet with multiple tables and a running lab. Trace input events, top-level renders, `cellMode` calls, detail-row formatting and paint. Compare default view, a filtered view, and resizing within and across the table/list breakpoint. See `webwriter-chemlab-periodic-table.ts:495–517,832–872,1226–1248`.
2. Keep the latest slider state immediately available and coalesce visual updates to one animation frame if the trace shows redundant per-frame renders. Flush the final input on gesture completion and preserve keyboard adjustments. Cache matches and the matching set by normalized query, language and family. Derive mode presentation only when the relevant conditions or year change. If the per-cell math shows up in profiles, compute the common pressure adjustment once per state, using the same model and threshold comparisons. See `periodic-table/phase.ts:171–200,289–310`.
3. Keep stable per-element labels and print-grid markup separate from dynamic values. Reuse formatted detail rows for the selected element, locale and conditions across screen and print where the content matches. Keep print and exported HTML in sync with the last slider state. Defer the hidden sources dialog body until opening only if profiling shows meaningful preparation cost. See `webwriter-chemlab-periodic-table.ts:1050–1083,1173–1222`.
4. Fix the resize observer lifecycle as a small, separate follow-up. It is created in `firstUpdated` and disconnected on removal, while `connectedCallback` currently only restores the language observer. Reattach it on connection and use CSS for widths that stay in the same resolved layout if testing confirms the width has no other JavaScript consumer. See `webwriter-chemlab-periodic-table.ts:306–328,369–376`.

**Acceptance.** Slider motion leaves search results, selection and focus stable. Verify final temperature, pressure and year after pointer and keyboard input. Compare all cell states and selected details to the current boundary tests, including unknown values. Preserve print details, screen-reader labels and offline use. Verify that a moved or reinserted widget switches layouts at the breakpoint. Keep the table work separate from the lab optimization commits.

# Molecule Builder implementation specification

This expands the design backlog into four implementation packages. It describes the intended runtime behavior, the code paths to change, and the checks that define completion. The starting point is commit `2afb3e9`, which added ion colours, lattice positions, worksheet-scoped sending, and the 40/60 grid layout.

## Scope and invariants

- Keep the builder usable alone, in a worksheet with ChemLab, and with a linked standalone periodic table. The embedded table remains the element picker. Its compact styling and interaction changes apply only under `picker-mode`.
- Keep both 3D and SVG editing. 3D continues to initialize lazily and render on demand. WebGL failure leaves a usable 2D editor and a clear explanation.
- Keep the existing chemistry, reference coordinates, dose permissions, and `.chemlab-structure.json` version 1. Panel state, tool selection, overlay flags, camera state, and displayed cell repetition belong to the widget session. The authored JSON and file downloads carry the structure.
- Keep `viewCatalogStructure`, `viewStructure`, and `reviewBuilderStructure` as the inter-widget entry points. Keep the existing element selection and drag events, `element-source-id`, `lab-id`, and `molecule-builder-id`.
- The target UI is bilingual. Use the builder’s translation path for labels, accessible names, hints, validation, and statuses. Keep chemical formulas, catalog keys, IDs, symbols, and space-group notation independent of the displayed language.

## 1. Establish one control hierarchy

### 1.1 Document header and canvas layout

Replace the current stack of `.toolbar`, open `.controls-panel`, `.tools`, and duplicate palette actions with three persistent regions. Use CSS Grid for workspace allocation and flex groups for controls.

```text
┌ Document: structure name · status                  Catalog  File  Send ┐
├ Editing: Select  Place O  Bond ▾              Undo  Redo        Elements ┤
│ ┌ Scene ─────────────────────────┐ ┌ Elements when docked ─────────┐  │
│ │                         3D model│ │ List / Grid, when available  │  │
│ │                                 │ │ Embedded periodic table      │  │
│ │                 2D  3D  −  + Fit│ │                               │  │
│ └─────────────────────────────────┘ └───────────────────────────────┘  │
└ Model readout and legend                       Selected atom/site card ┘
```

The drawing shows the regions. The canvas view controls belong to a bottom rail within the canvas frame but outside its pointer surface. The palette handle attaches to the drawer edge. The readout and inspector share a bottom region beneath the canvas column. On narrow layouts, controls wrap in their current logical order, the palette overlays the right edge, and the readout and card stack. Use ordered DOM for the same progression the user sees. The stage owns the Pixi host and SVG, receives pointer and wheel events, and is the bounding rectangle for placement, picking, and fit.

- **Document header.** Use a text heading for the current structure, one quiet status tag, then Catalog, File, and the conditional ChemLab action. Use the catalog’s display name when the model has a catalog key and the current preview is that compound. Otherwise use the authored name, then a calculated formula, then localized **Untitled molecule** or **Untitled crystal**. Put the formula in the model readout only when it adds information. When a preview’s name identifies an individual constituent, keep the parent compound in the heading and the constituent in the preview controls. Keep long titles readable via wrapping in narrow layouts and a single-line ellipsis in wide layouts with the full value available on focus.
- **Editing rail.** Keep the selection/orbit action, atom-placement action, and molecule-only bond action together. Label the first action **Select** in 2D and **Select / rotate** in 3D. Place shows the active element symbol and exposes its localized name in its accessible label, for example **Place O** and **Place oxygen atom**. Use one group of named controls with `aria-pressed` and a distinct focus outline. Style stateful native buttons with the same tokens and use `sl-button` for ordinary commands. Keep Undo and Redo present and disabled when their stack is empty, so the rail stays in place after the first edit. The bond order control occupies the adjacent slot only with Bond active. Use one compact labelled selector or three immediately adjacent toggle buttons with accessible names Single, Double, Triple. In either case use the current `bondOrder` value, preserve it when switching tools, and keep pending connection endpoints when changing only the order. Keep **Fit geometry** in molecule details or an anchored editing overflow, available where the existing editor supports it. Label its help text as an estimate and keep it an undoable structure edit. **Fit view** belongs only to the camera rail.
- **Canvas view rail.** Put **2D** and **3D** first, then the current model’s **Display options**, then minus, plus, and **Fit view**. Disable 3D while WebGL is known unavailable and announce the reason once through the existing status. Keep zoom buttons in 3D and expose only Fit in 2D during this work. Use explicit accessible names for icons and the same zoom signs, border radius, light gray surface, and shadow as ChemLab’s canvas buttons. Make the 2D versus 3D names literal. Give preview mode the same controls in the same locations.
- **Preview controls.** The preview gets a visible **Preview** tag, **Edit copy** as the single primary action when a model exists, and a default **Return to draft** action. The rail can show its constituent selector next to these actions. Hide topology editing actions and the palette. Keep selection, display controls, export, and conditional sending accessible in preview. In draft mode, **Send to ChemLab** can be the primary document action when available, while tool selection uses a tinted active state.
- **Styling.** Build outward from the existing `--canvas-control-surface`, `--canvas-control-shadow`, and `--lab-card-shadow` in [ChemLab styles](../chemlab-style.ts), and the table’s `--pt-*` surface and focus tokens. Use private builder variables for the initial restyle. Extract a shared CSS fragment only for identical values that these widgets directly consume, if the third use warrants it. Keep each widget’s scoped theme and component registration. Give the widget a subtle outer outline, a quiet stage background, and a clearly bounded palette. Reserve the emphasis of the card shadow for the inspector and anchored surfaces. Apply logical insets and the installed Shoelace size presets. For frequently used canvas and drawer actions, use at least a 32 CSS px target as a starting value, increasing the interactive area to around 44 CSS px on coarse pointers where there is space. Keep the inner icon size stable.

Verify that opening a control, creating an atom, rotating, and running Undo never change the order or alignment of the other commands. Check different text lengths in English and German, including **Zellen pro Achse**, a long catalog compound name, and an empty structure.

### 1.2 Anchored catalog, file, and target surfaces

Use Shoelace `sl-popup` as positioning infrastructure for the three surfaces. The catalog contains a labeled input and results, so use ordinary form controls and buttons inside its labeled region. The file surface consists of simple actions. The target surface lists the available receivers and uses the same shell. Keep the Popover implementation consistent with ChemLab’s use of Shoelace popup and the installed scoped registry. [Shoelace Popup API](https://shoelace.style/components/popup)

1. Replace `openPanel` plus `showLabs` with one UI state for the active temporary surface, such as `"catalog" | "file" | "targets" | "display" | "model-details" | null`. Use Lit render methods and stable keys for the persistent triggers. Keep preview state independent. Opening a different surface closes the previous one. Give triggers `aria-expanded`, `aria-controls`, and an accessible name. Put those attributes on the actual focusable button. The installed Shoelace button renders a focusable button in its own shadow root. Use a native button styled with shared tokens for disclosure and toggle controls if the shipped component does not expose the attributes on that focusable node. Keep the controlled ID in the same shadow root as its trigger. Register each new Shoelace element in `static scopedElements` with its own component import. [WAI disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)
2. Pass the actual trigger node as `.anchor`. Use `bottom-start` for header popups and `top-end` for controls near the bottom, with `flip`, `shift`, and `auto-size="both"`. Bind limits to the builder’s usable rectangle where Shoelace exposes boundary properties. Start with 6–8 px trigger clearance and a catalog panel around 22 rem that can shrink to the actual widget width minus margins. Use the available size CSS variables on the panel, a fixed header, and an overflowing results area. Try `strategy="absolute"` first in the real WebWriter wrapper. Verify at least one scrolled worksheet and one builder flush with the viewport edge. If a containing block clips a popup in a supported host, use the installed fixed strategy where it behaves correctly. Use an in-frame panel below the header as the compact fallback when the popup cannot expose a usable result area. Keep that fallback under the same state, focus, and close rules.
3. Open by click, Enter, or Space. Focus the catalog input for keyboard activation and the first actionable row for File or Targets. Allow Tab to leave a surface. Close on an outside pointer down, Escape, a completed selection, or when its context disappears. Outside dismissal preserves the user’s intended pointer focus. Escape and cancel restore focus to the trigger after Lit updates. On keyboard-triggered successful catalog selection focus the preview’s first action, and on successful send focus ChemLab’s review heading or first review action once rendered. When leaving by Tab, test the focus destination using the composed focus path and close without moving it back. Use `ownerDocument` and `composedPath()` for outside detection with nested Shadow DOM. Install document listeners only for an open surface with an abortable lifetime. Clicks in the popup’s descendant controls belong to the surface. [WAI button focus guidance](https://www.w3.org/WAI/ARIA/apg/patterns/button/)
4. Anchor the catalog popup to **Catalog**. Transform the existing grouped catalog selector into a labelled search field and a list of named buttons, grouped in the existing category order. Index lowercase names and formulas once. Fold combining accents, map Unicode subscript digits to ASCII for formula searches, and tokenize on whitespace. Keep current spelling and symbols in results. Give an exact match priority within its category, including a formula such as `CuSO4`. Keep full results scrollable and use Lit keyed repeat if needed to retain a row’s focus. Use Arrow Down from the search field to enter the first result and provide a normal Tab path through available actions. Keep search text while the popup is open and select its contents on reopen so a new query is easy. Use a short **No matches** status only when a query has no results. Keep category and compound identifiers from `structureCatalog`. Resolve coordinates through `catalogStructures` when the user activates a result.
5. Close the catalog surface on opening a structure. Move the variant chooser from the old catalog panel to the preview region, so choosing another constituent stays available when the popup closes. Keep the variant control when multiple structures are returned. Label options from model name plus localized representation where needed and preserve order from `catalogStructures`. A known catalog compound with zero variants enters a catalog information state with a clear reason and a **Return to draft** action.
6. Keep a single hidden file input mounted for the widget’s lifetime. Open it from the click handler itself to preserve user activation. Reset its value immediately after extracting the selected File, and share `#openFile` for that path and the existing dropped-file path. Keep the File surface’s **New molecule**, **New crystal**, **Open file**, and **Download**. Disable Download for empty structures. Keep New and Open undoable through `#record`, and keep `readStructure`, byte limits, and request-token checks. On a canceled file chooser restore focus to File without changing the current document. On an invalid file show localized status and leave the existing draft or preview available. On success close the file surface, clear stale selection, and fit the newly loaded draft.

### 1.3 Pointer and keyboard ownership

- Bind board handlers to a dedicated `.stage` inside the visual frame. Move button and inspector markup out of that node. Replace `#insideBoard` with a client-coordinate stage test. For releases from an external palette, additionally check the topmost visible hit target in the builder’s shadow tree to exclude the drawer, popups, and other controls overlaying the stage. Check the rectangle and hit elements in client units. Use the unchanged inverse SVG transform or Pixi coordinate mapping for accepted drops.
- Keep the existing 5 CSS px threshold between tap and drag. Reset captured pointers, preview lines, and any drag ghost for cancellation, blur, view change, or removal. Guard `setPointerCapture` with a live pointer handler and tolerate lost capture. Never translate a pinch into a tap. Keep native page scrolling over the palette, readout, and header.
- Handle builder editing shortcuts only when the active composed path belongs to the stage or an editing control that shares the shortcut scope. Leave inputs, select controls, popup navigation, hidden file input, and the authoring host their own keys. Process Escape from the innermost open surface first, then an active drag or unfinished bond, then selection or preview via explicit controls. Only consume a key when an action ran. Preserve Undo/Redo via Ctrl/Cmd+Z and Shift+Ctrl/Cmd+Z. Add a test for keyboard undo while a details field is focused so a Browser/WebWriter text edit stays inside that field.
- Use the existing live output for errors and meaningful transitions. Continuous orbit, hover, drag coordinates, and every search keystroke need no announcements. A pending bond can announce a short **Choose the second atom** message after the first endpoint is set.

## 2. Make the element palette adapt to the worksheet

### 2.1 Layout resolution and drawer

Keep one embedded `webwriter-chemlab-periodic-table` node mounted across layout changes. Pass the effective `.view`, `.selectedAtomicNumber`, and `picker-mode` as now. Keep full-width authoring state separate from the available child width and the user’s layout preference.

| Host condition | Default or effective state | Interaction |
| --- | --- | --- |
| Compact workspace under an initial `42rem` | List drawer collapsed on first visit | Attached right handle opens the overlay. Remember this mode’s open choice for the session. |
| Room for a docked palette | List by default | Right-side dock in the workspace grid, starting at `clamp(12rem, 30%, 17rem)`. Expand or collapse with the same handle. |
| `ww-full-width`, enough room for grid | List initially, grid when chosen | Grid gets `2fr` and stage `3fr`, giving 40% to the table. List keeps the narrower dock. |
| `ww-full-width`, grid preferred, currently too narrow | Effective list | Keep the grid preference and restore it when the measured width is sufficient again. |
| Preview or a temporarily hidden widget | Palette hidden | Restore the remembered draft preference after returning to the editor. |

- Measure the workspace content width using one `ResizeObserver` for responsive state, separate from the renderer’s size observer. Start with a required `23rem` outer grid column. The embedded table currently uses a `21rem` grid minimum, so the remaining `2rem` covers chrome, the handle edge, and the scrollbar. The first width threshold for the 40% split is therefore `57.5rem`. Use the computed root font size or an equivalent rem measurement. Subtract any actual column gap before applying 0.4. Compare the predicted grid column from the workspace width even while in list mode, so the renderer cannot repeatedly toggle due to its own measurements. Write reactive state only when the resolved band changes. Add approximately 8 CSS px of hysteresis between entry and exit if resize causes flicker. During the WebWriter test, record the narrowest width that fits the last group and labels without horizontal clipping. Adjust the proposed values from that measurement.
- Show the view switch only when `ww-full-width` is present. With the class and insufficient space, leave List selected and disable Grid with a short accessible reason. Without the class hide the switch and force effective list. Observe live class changes, as now. A prior manually chosen Grid can return when the class and width permit. Initial no-preference is List. On resizes or class changes, restore focus to the selected element in the replacement layout when focus was inside the table. Focus remains on the original control for an explicit layout selection unless that control disappears.
- Keep CSS responsive placement and JS layout resolution aligned through one measured `data-layout` value or a single documented breakpoint shared by both. Use logical `inset-inline-end` for the overlay. Give it `min(18rem, 80%)` width in compact mode and limit its height to the stage frame. Maintain a single scrolling body in the embedded table. Set all flexible ancestors in that axis to `min-block-size: 0` and `min-inline-size: 0`. Avoid a second scrollbar on the palette and keep the rest of the worksheet scrollable. Respect reduced motion, and keep the animation out of the render ticker.
- Style the handle after ChemLab’s palette grip. A collapsed grip shows the elements icon and inward chevron. Expanded, it is attached to the drawer’s canvas-facing edge with an outward chevron, the same surface, and a border meeting the panel seam. Give the handle a stable DOM node, a descriptive label, and `aria-controls` plus `aria-expanded`. Move it with layout, keeping focus visible. Close by handle, via Escape from inside the compact palette, or on an outside tap in compact mode. Consume the dismissing tap when it lands on the stage to prevent an unintended atom insertion. Keep docked mode available while editing. Start with a short opacity/translate transition for compact mode and an immediate grid-column change for docked mode. The camera can handle the latter in one settled fit calculation under the rules in §4. [WAI disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)

### 2.2 Selection, touch, dragging, and keyboard placement

- Keep atomic number, localized name, symbol, and family accent on picker rows. Use the selected blue state and a separate focus ring as in the grid. Reuse the family accent assigned by `categoryOf` and the table’s colour tokens. Remove the duplicate active-element tag from the drawer heading. Keep one selected-element representation on the placement button and the highlight on the row. Move **View crystal** into a contextual row action below the picker or an overflow next to the highlighted element. Show it only with a stored lattice. Expose a missing bulk lattice through model information if the user explicitly opens element context. A metal crystal preview uses `viewStructure` and preserves the user’s draft.
- A row click or keyboard activation chooses the element through the current selection event and activates Place. In compact mode close the drawer on explicit row activation and move keyboard focus to the stage. In docked mode keep the list open and focus on the row for continued browsing. Keep selecting the already active element usable to re-enter Place after using Bond or Select. Update `#selectFromUser` in picker mode. It currently returns when `SelectionModel.select` reports that the value was already selected. Dispatch one explicit selection event for a new user activation of the same picked element. Keep externally assigned selection silent and keep the standalone table’s existing change-event behavior.
- **Touch tap flow.** Open the handle, scroll, tap an element, then tap an unoccupied stage location. A tap on an existing atom selects the atom. With the narrow drawer open, scrolling the list keeps the current atom count. The touch flow must work with the SVG fallback. Use the existing `touch-action` on the scene/SVG and allow `pan-y` within the element list. Avoid starting a drag from an interactive row command. Keep the existing mouse, pen, and compatible touch drag path. On platforms where touch scroll cancels drag from the row, the tap flow supplies full placement without requiring a touch drag. [WAI alternatives to dragging](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements)
- **Keyboard flow.** Use the embedded grid’s existing navigation behavior. For picker list, define one roving focus position per list so Tab can leave the 118 rows in one step. Use Up, Down, Home, and End to move without selecting. Scroll the focused row into view in its own pane. Enter or Space applies the element through the same choose path as a click. With focus on the stage and Place active, Enter or Space uses the `#addAtom()` default position, which creates exactly one atom through the same validation and undo path. Announce the chosen element and the key on first activation or in the stage’s accessible description. Focus returns to the stage after a committed placement. When the drawer is collapsed, offer a direct focus path to the handle and keep closed content out of the tab order. Keep native list and button semantics for this interaction.
- **Drag flow.** Retain the `chemlab:element-drag` protocol. Start a ghost after the threshold and tag it with the corresponding primary pointer. Make the ghost `pointer-events: none` and update it while dragging. When departing a compact drawer, keep enough visible stage for drop and collapse the drawer once the pointer crosses into that visible stage strip. If the drawer settles before drop, remeasure the stage on release. Pass actual atomic number and placement to `#addAtom`. Releasing over a control, worksheet margin, another widget, or the drawer creates zero atoms. Cancel on Escape, pointer cancellation, window blur, disconnect, preview transition, or loss of a valid stage. Suppress only the trailing click from a completed drag, so a fresh row tap still works.
- **Linked table flow.** A selection in a standalone linked table changes the builder’s active element via `SelectionRouter` and updates the highlight. Leave focus and scroll where the user was in the standalone table. Leave a compact builder drawer closed. If a preview is active, remember the chosen active element for the draft and leave preview mode unchanged. Test that a second unlinked table and another worksheet never change this builder’s state.

### 2.3 Palette acceptance

Check compact and docked behavior at roughly 320, 480, and 720 CSS px, plus a wide host above the measured grid threshold. Include a wide viewport with the builder in a narrow worksheet column and a full-width builder in a short viewport. Assert the class gate and the measured ratio in the actual rendered columns. Change the class while the grid has focus, change the width repeatedly around the threshold, and verify there is one table instance with the same selected element. Keyboard-only and touch users can both choose and place a new atom in 2D and 3D. The standalone periodic table still offers its original layout controls, table modes, filters, and cards.

## 3. Separate model information, selection, and preview state

### 3.1 Model readout and selected-site card

Replace the full-width inspector with a single bottom readout region inside the canvas frame. On a wide canvas, use a grid with a flexible readout and a selection card slot roughly 12–17 rem wide. Place the summary at the start and the compact card at the end. Below the width where both remain readable, stack them in that order. Keep the canvas’s own minimum block size and allocate additional page space to stacked controls. An open inspector must never cover the centre of the molecule or move with the pointer or orbital angle.

| Region | Visible at rest | Expanded information |
| --- | --- | --- |
| Model readout | Formula if informative, model type or representation when relevant, active display legend, and a **Details** action | Source and representation, model-level conditions, editable or measured unit-cell metrics, and **Fit geometry** where applicable. |
| Selection card | Element symbol, atom/site identifier, optional ion formula or isotope, and Clear and Delete where applicable | Formal charge, radius model, supported geometry, position, occupancy, and individual bond controls. |
| Atom/site chooser | A labelled **Choose atom** or **Choose site** control for a nonempty structure. Place it after the readout. | List base-cell IDs for a crystal. Keep current selection available when the visible repeat count grows. |
| Status output | Errors or short action feedback when present | No reserved full-width message strip when empty. |

- Use one title for each level. Show the catalog name or draft name in the header. Use the readout for the relationship between the displayed structure and the record, such as a **Computed conformer**, **Estimated geometry**, **Ionic components**, or **Mixture constituent** tag. Keep **Sketch** for editable graphs without geometry metadata where it communicates a relevant limitation. Group source, representation, measurement conditions, and limitations in the same **Details** surface. Expose an external source as a labelled HTTPS link with the current safe target attributes. Give the legacy catalog-density case its estimate caption. Preserve explicit conditions such as unavailable hydrogen coordinates and applicable temperatures.
- Render a selected atom/site card only for a valid `picked` ID in the current model. Use the ChemLab info card treatment for the surface, shadow, compact tags, and icon-only removal. Add a distinct accessible **Delete atom** or **Delete site** label to a danger-styled button, then route through `#removeAtom` to keep undo and removal of incident bonds. Clear has a different icon, title, and handler. It changes only the selection and pending bond state. On keyboard deletion focus the atom chooser if entries remain, otherwise focus the stage. Keep the first-party tooltip if needed, with focus visible independently of that tooltip.
- Key selection by stable atom or site ID. The 3D scene currently maps repeated meshes to one site ID. Keep all periodic copies highlighted when that base site is selected. Show the base cell fractional coordinates and identify them as such. Remove selection on a draft change when the ID no longer exists. Undo/redo may restore a previous snapshot with the same ID. Follow the existing selection reset until the history implementation carries an explicit selected ID, so a stale ID never selects a different atom by coincidence.
- Split pure inspection (`picked = id`) from an editing gesture that may set a bond endpoint. For example, use `#inspectAtom(id)` for the chooser, and a separate `#useAtomAsBondEndpoint(id)` path for stage clicks in Bond. A chooser must not create or change a bond because the Bond tool happened to be active. For keyboard-only bonding, provide an explicit **Set first endpoint** or **Connect to selected atom** command when Bond is active. Reuse `canBond`, the current bond order, and `#connectBond` to commit one undo step. Keep current click-to-click and drag-to-connect behavior, and use the status output to explain invalid valence.
- Move material-specific fields out of the card’s compact face. In atom mode provide formal charge, current radius in pm with its source model, and a supported shape if determined. Show molecular Cartesian `x/y/z` values in Å in the advanced section for reference. For a crystal site show fractional `x/a`, `y/b`, `z/c`, occupancy when reported, formal charge where relevant, and the curated ion label where present. A polyatomic ion label identifies membership. Label the formal charge field separately to prevent confusion. In the crystal model details, present cell lengths, angles, space group, Bravais type, temperature, conditions, and a partially occupied sites indicator. Keep bond removal next to the bonds of the selected draft atom.
- Reuse `#updateCharge`, `#updateCell`, `#updateSite`, and `#record` for edits. Keep current validation and limits, including finite coordinates, fractional `[0, 1)`, the duplicate-site check, integral charge, and a valid cell. Commit an input on `change` or explicit Enter through the same handler. On invalid input restore the committed value and expose the reason near that field or through the status region. Use editable native number inputs for numerical values and text or a definition list for preview values. Display rounded values while retaining the full numeric precision in snapshots. Localize the displayed formatting. Use native value parsing for edits and avoid parsing the localized readout text.
- Keep the short card visible by default when selected. Use a native disclosure or `sl-details` for its advanced fields in a docked readout; if expanded content would push the editor out of view, present it in the same anchored surface mechanism as model details. On a compact width, constrain scroll to the advanced body. Keep trigger and focus position stable across selection changes. If a model swap removes its actor or action, close the open details surface and focus a remaining control only when its contents held focus. Every pointer and wheel event in the readout is outside `.stage`.

### 3.2 Draft, preview, and empty catalog entry transitions

The current code stores `preview` alongside `catalogKey`, `catalogVariants`, `catalogIndex`, and `openPanel`. Consolidate presentation state so a compound with zero structures is a first-class outcome. An example shape is a discriminated union with a draft state, a reference state carrying a validated snapshot and optional catalog context, and a catalog-information state carrying the known key and the reason no model is displayed. Keep the editable draft, the undo stacks, and the file request generation independent.

| Transition | State and rendering | Focus and persistence |
| --- | --- | --- |
| Catalog selects an entry with variants | Enter preview with the first variant, attach parent catalog context, show the variant control when length exceeds one, and fit the reference. | Close the catalog surface. Keep the previous draft and history in memory. Persist nothing. |
| Catalog selects a known entry with zero variants | Show the specific reason on the canvas region, with the compound title and **Return to draft**. Hide placement, export, send, and model-specific controls. | Acknowledge the entry as handled. Keep the draft intact and discourage accidental interaction with an unrelated model. |
| Standalone ChemLab sends a valid structure | Enter reference preview through `viewStructure`. Build title and type from the validated snapshot. | Keep current worksheet scope. Preserve the in-progress draft. Cancel stale file-load requests. |
| Invalid incoming structure or unknown key | Return failure through the existing boolean API and retain the current visible context. | Leave focus, history, and persistence alone. |
| Change variant | Replace the live preview and reset stale IDs, pending gesture state, and the previous variant’s fit. | Keep focus on the variant control. Save no draft change. |
| Return to draft | Restore the draft view and its tool, selected ID if valid, repeats, and palette preference. Restore camera position in manual mode when possible. | Restore a stable trigger or the stage. Leave the previous draft and history exactly available. |
| Edit copy | Validate and copy the reference snapshot into a fresh editable object via `readStructure`. Record it as one undo step. | Enter draft mode and focus its stage. A subsequent edit uses existing metadata invalidation rules. Undo can recover the prior draft. |
| New or successful file import | Replace the draft through `#record`, exit preview, and schedule fit. | Keep the action undoable and persist according to the existing WebWriter authoring guard. |

- Capture draft view context once when leaving draft. While moving between reference items, avoid overwriting it with preview state. Store it in memory alongside the draft state. At minimum store view, manual camera pose or auto-fit mode, tool, repeats, selection, and the palette preference. Keep the active element outside that saved context so selections from a linked periodic table can update the draft while a preview is visible. For preview choose the current display mode if supported. Start new preview crystal repetition at one. Keep model-type overlay preferences independent so an electron overlay never appears on a crystal.
- On dismissal, preserve an existing pending draft only with its relevant context. Cancel active pointer capture, pending bonds, and a diagram drag before taking the preview snapshot of the view context. Undo/redo are draft-only operations. Exit a completed preview without preserving a half-drawn bond.
- Preserve distinct labels for a catalog reference, an actual model copied into a draft, and a named imported structure. The presence of a catalog key alone does not make a draft read-only. A model without a verified structure can still have a named catalog record. Keep the user’s prior draft out of that information screen until they return to it.
- Use the existing race guards around saved data restore, file reads, disconnect, lazy 3D initialization, and context loss. Every accepted command that supersedes an in-flight file open should invalidate its request generation. If the author updates the stored draft while a reference is displayed, update the draft snapshot independently and invalidate any saved draft selection that is no longer meaningful. When a scene initializes after a view change, draw the current model when returning to 3D and apply only the pending fit for that context.

### 3.3 ChemLab handoff and focus

## 4. Improve fit and crystal readability

### 4.1 One stage rectangle and two fit implementations

Use the actual canvas stage content box for all camera and pointer calculations. The view rail, inspector, and top-level controls occupy their own CSS tracks. - Establish stage padding from its short edge, starting at approximately 8% per side, clamped to 12–36 CSS px. Reduce it for tiny measured stages so there is always positive image area. Keep a guarded positive fit floor. Expose separate read-only geometry state for the stage size and the view’s scale. When stage size is zero, defer fit until the next usable measurement.
- Compute 3D fit in CSS px and world units. Derive camera aspect from the actual Pixi stage and retain the renderer’s capped device pixel ratio. Establish one call path for Fit, preview fit, new-model fit, and responsive auto fit. 2D and 3D fit are different projections of the same structural geometry.
- Put pending fit mode in the view layer. A newly opened draft, a new reference, an explicit repeat count change, **Fit view**, and committed **Fit geometry** use auto fit. Rotate changes yaw and pitch while retaining the current target and camera distance. Zoom switches to manual. A view switch preserves each view’s pose when it is already initialized for that model.
- Separate fit dirtiness from ordinary renders in `updated()`. Replace the unqualified `#fitNext` with a pending request associated with the current renderable model and view. Keep manual zoom steady during resizing or a focus change.

### 4.2 Perspective fit in `MoleculeScene`

Replace the current centre-only maximum radius and `2.7 / aspect` heuristic with a frustum calculation using the installed `Camera3D.fov`, `.zoom`, and `.near`. Keep the camera perspective and current yaw/pitch. Use the renderer’s actual geometry scale and one type such as `{ center: Point3, radius: number }` for extent contributions. [PixiJS 3D 0.1.0 camera API](https://3d.pixijs.download/v0.1.0/docs/scene.Camera3D.html)

1. Build extents when structural geometry or repeats change. Each sphere contributes its model centre and the exact radius used by `#atom`, including the selected radius model and crystal scale. Each bond cylinder contributes endpoints with its tube radius; include every offset for a multiple bond. The convex hull between those endpoint spheres bounds the cylinder. Crystal edges contribute their endpoints and stroke radii, and the eight displayed supercell corners anchor the framing when cell aids are active. Include active electron glyph extents if the control is on, using a conservative radius or ellipsoid-supported bounds for the displayed lobe. Use the same atom radii and cell coordinates already consumed by rendering. Exclude transient drag or bond previews.
2. Determine an initial target from the midpoint of the combined AABB. Use the camera basis built from the yaw, pitch, and world-up direction under the same convention as `lookAt`. The `back` axis points from target toward eye. With world-up `[0, 1, 0]`, use `right = normalize(cross(worldUp, back))` and `up = cross(back, right)`. Compare the signs against `worldToScreen` at the default orbit angle before wiring the helper into picking and rendering. Use the existing pitch clamp to avoid a singular world-up orientation. For each centre relative to target, compute `x = dot(delta, right)`, `y = dot(delta, up)`, and `z = dot(delta, back)`.
3. Let `W` and `H` be the visible stage and `pad` the safe symmetric margin. The vertical tangent before the margin is `tan(fovRadians / 2) / camera.zoom`. Calculate `ty = verticalTangent * (H - 2*pad) / H` and `tx = verticalTangent * (W/H) * (W - 2*pad) / W`. Compute the distance required by the left/right, bottom/top, and near planes for every extent centre with radius `r`. Because each constraint is a plane, the support of a sphere along its normal is the radius times the normal’s length.

   ```text
   minimum for X:    z + (abs(x) + r * sqrt(1 + tx²)) / tx
   minimum for Y:    z + (abs(y) + r * sqrt(1 + ty²)) / ty
   minimum for near: z + r + near + clearance
   fit distance:    max(minimum for X, minimum for Y, minimum for near)
                    over all extents, with a small numerical safety margin
   ```

4. Set the eye to `target + back * distance`, then call `lookAt(target)`. Size the far plane to enclose all bounds with a margin. Keep near finite and positive. Use a default `target = [0, 0, 0]` and a documented default distance or current empty-scene value when no geometry is visible. Use an appropriate camera-distance cap for validated input. Check the existing manual maximum of 40,000 world units against the largest accepted coordinates and narrowest stage. Use a coherent fit and manual range so the calculated fit distance remains reachable.
5. Measure actual output using a screen projection of extreme geometry on several structures. Start with a goal that a simple model occupies roughly 70–85% of its limiting stage dimension after Fit. Scene geometry and the margins determine the outcome. Elongated or jointly visible shapes can fill one axis while leaving room on the other. Fit at the current orbital angle and retain scale during subsequent rotation. Users can refit after changing the angle. Test fitting again after orbiting about a non-axis-aligned orientation.

Put camera math in a pure function with a narrow input and output. Unit-test an asymmetric cloud, sphere near an edge, shifted extents, very narrow portrait and landscape viewports, empty/degenerate inputs, and the near plane. Simulate applying the computed camera, then assert all contributing extents fall inside the safe frustum. Verify expected sizes using precomputed examples and compare screenshots with the old wide canvas.

# ChemLab structure library

The library supplies offline structures for the existing chemical catalog. It is separate from ChemLab's dosing and equilibrium models. Molecule Builder shows the archived structure with its source. ChemLab checks a returned structure against the catalog and the worksheet's reagent permissions before selecting a dose.

## Molecule Builder → ChemLab compatibility handoff

### Required outcome for the next implementation

Every compound selectable in Molecule Builder must be directly usable as a reagent in ChemLab, rather than being transferable only as a structural reference. This is a catalog-wide requirement covering molecular compounds and crystal references, not just organic compounds or the NaHCO₃ example. The current implementation does not yet meet this requirement across the catalog; this section is the handoff for future work, not a claim of completed coverage.

For every listed salt, provide **both a solid-salt form and an aqueous-solution form**, with explicit phase selection and concentration controls for solutions. A crystal handoff should select the solid form; an aqueous-ion overview should select its corresponding solution. Both forms must resolve to the same analytical compound and shared chemical models. Respect actual solubility: a sparingly soluble salt still needs a usable solid and a physically valid solution option, with appropriate concentration limits and undissolved excess where applicable. Do not silently substitute a solution for a selected solid, or treat a salt as fully dissolved beyond its modeled limit.

Compatibility includes dosing, chemically appropriate behaviour within the simulation's documented scope, interaction with existing reagents, and save/restore. Existing reagent permissions and structural validation remain in force. Missing identity data, recipes or chemistry models are implementation gaps to resolve for selectable catalog compounds, not a permanent reference-only exemption. Track them explicitly until the catalog-wide requirement is satisfied.

### Manually edited inorganic compounds

The required pipeline also covers **manually altered inorganic molecules and salts**, including edited catalog references and custom structures, using the same structure-based identification and enrichment workflow already available for organic compounds. They must be identified from their current chemical structure and, after validation and data lookup, become usable ChemLab reagents. Support must not depend on an unchanged catalog structure or an organic classification.

Editing must invalidate stale compound identity, fetched facts and dosing recipes. Re-identify the current graph or analytical salt formula, preserving complete polyatomic ions, formal charges, protonation state, stoichiometry and hydrate composition. Distinguish chemical changes from changes to drawing layout or viewing geometry. An edited reference must not inherit approval or chemical data merely from its old catalog key; failure to match the original recipe must route to fresh identification rather than automatically ending at reference-only storage.

For manually altered salts, lookup and validate **all data required for both solid and aqueous forms**: exact compound identity, phase/hydrate identity, molar mass, solid density, solubility or Ksp with units and reference conditions, and relevant acid/base, hydrolysis, complexation and other interaction data. Retain sources and resolve conflicting measurements. If the edited crystal does not establish a unique analytical formula or phase, report that specific unresolved input instead of inventing one.

Use the fetched, validated data to generate both solid and solution recipes and drive the actual solubility simulation, not only a concentration selector. Model finite solid reservoirs, dissolution, saturation, precipitation, dilution and relevant coupled equilibria consistently with existing reagents. The same salt dosed dry or in solution must reach equivalent results for equivalent final composition and conditions. Respect temperature/phase limits of the available data and document approximations. Reuse the existing carbonate and bicarbonate families rather than creating independent systems for newly identified members.

Incomplete or chemically invalid structures, ambiguous identity, missing measurements and unavailable simulation models must produce actionable reasons and remain tracked implementation gaps. Do not silently accept an arbitrary formula, guess required properties or claim correct simulation without the supporting model. Identification, validation and reagent permissions still apply to custom compounds. This extension is future implementation work; the NaHCO₃ catalog recipes below do not already implement it.

### Implemented example: NaHCO₃

Sodium bicarbonate has a dry-salt recipe under the existing `Natriumhydrogencarbonat` catalog key and a separate prepared aqueous stock under `Natriumhydrogencarbonatlösung`. Returning its unchanged archived crystal selects the dry salt through the existing structural comparison and worksheet permissions; the aqueous preview selects the stock. The solid formula unit has one ionic Na–O relationship and an explicit O–H bond. Its starting atoms are neutral because the graph loader applies the ionic charge transfer. Solvation splits the unit into Na⁺ and HCO₃⁻ and registers any excess as a solid reservoir. The CIF has no hydrogen positions and must not supply the analytical formula. The aqueous preview includes the proton and uses the conventional HCO₃⁻ label.

Both forms share the existing carbonic-acid family with `Natriumcarbonatlösung` (pKa 6.35 and 10.33). Bicarbonate starts at the intermediate protonation step with one sodium per carbon, whereas carbonate has two. Acid/base addition, CO₂ release, precipitation and saved mixtures use the shared simulation rather than a bicarbonate-specific reaction. The nominal room-temperature saturation limit is 1.14 mol/L, approximately 96 g/L divided by 84.01 g/mol; the solid-density parameter is 2.16 g/mL. Sources: [Solvay product safety summary](https://www.solvay.com/sites/g/files/srpend221/files/2021-01/PSS-Sodium-Bicarbonate.pdf) and [Sigma-Aldrich sodium bicarbonate](https://www.sigmaaldrich.com/US/en/product/sigald/s6014). The existing ideal-concentration and gas-saturation approximations still apply; this does not add thermal decomposition or atmospheric CO₂ exchange.

### Implemented example: potassium halides and nitrate

Four further salt identities now carry both forms: `Kaliumchlorid` with `Kaliumchloridlösung`, `Kaliumbromid` with `Kaliumbromidlösung`, `Kaliumiodid` with `Kaliumiodidlösung`, and `Kaliumnitrat` with `Kaliumnitratlösung`. The aqueous stock takes its concentration limit from the tabulated saturation in `chemlib/saltSolubility.ts` (4.02, 4.57, 6.09 and 2.77 mol/L), the dry salt carries the tabulated solid density (1.98, 2.75, 3.12 and 2.11 g/mL), and both resolve to the same analytical compound: a dosed solid dissolves, settles at the same saturation as the stock and redissolves on dilution. The three halides reuse the existing chloride ion; bromide, iodide and potassium are new ion definitions, and every fragment matches its table SMILES exactly (`[Br-]`, `[I-]`, and `[O-][N+](=O)[O-]` for nitrate).

Potassium nitrate is the first catalog solid whose polyatomic ion needs formal charges inside one formula unit. `Molecule.addBond` transfers charge along the ionic K–O bond by electronegativity, so the stored graph pre-compensates that transfer with `charges: [0, 1, 0, 0, -1]` instead of a naive K⁺/NO₃⁻ pair: the loaded formula unit comes out as `[K+].[O-][N+]([O-])=O`, the nitrate form of the table, and the dry salt dissolves into the same ions as the stock. The dry salts stand together in one solid block ahead of the stocks in `data/chemicals.ts`; the coverage report joins a pair by the catalog formula, not by position. Naming follows the bicarbonate pair: the stock keeps a distinct catalog key and a display name without the solution suffix, so the dry salt and the solution do not read as duplicates.

`tests/salt-forms.test.ts` covers all four pairs: catalog phase and concentration limit against the tabulated saturation, complete dissolution of 0.01 mol in 100 mL to 0.1 mol/L of each ion at pH 7, agreement with the same amount of stock, a saturated reservoir that conserves moles, and redissolution on dilution.

### Implemented example: sodium bromide and iodide

`Natriumbromid` and `Natriumiodid` were the last two solids without a stock, because neither salt was tabulated and a stock would have had no saturation limit. Both now carry a `saltSolubility` row, derived the same way as the other freely soluble salts: the saturated mass fraction converted with the density of that same solution (90.5 g per 100 g water as 47.5 % and 1.53 g/mL give 7.06 mol/L for NaBr, 184 g per 100 g water as 64.8 % and 1.84 g/mL give 7.95 mol/L for NaI). `Natriumbromidlösung` and `Natriumiodidlösung` take that limit, and the dry salts read their solid density from the same row. The table is now the single source for every dosed salt: `salt()` in `data/chemicals.ts` looks its entry up by catalog formula instead of taking a density argument, so a formula unit and its solid density can no longer disagree. `tests/salt-forms.test.ts` runs both new pairs through dissolution, pH 7, agreement with the stock and the saturated reservoir.

### Implemented example: ammonium chloride and sodium acetate

`Ammoniumchlorid` and `Natriumacetat` were reference-only entries with a builder crystal but no dose at all. Both are freely soluble and needed a `saltSolubility` row before they could carry either form, derived like the alkali halides from the saturated mass fraction and the density of that same solution: 29.7 g NH₄Cl per 100 g water at 25 °C is 22.9 % with 1.077 g/mL, which gives 4.6 mol/L, and 46.4 g sodium acetate per 100 g water at 20 °C is 31.7 % with 1.11 g/mL, which gives 4.29 mol/L. The dry salts take their bulk densities from the same row (1.527 and 1.528 g/mL), `Ammoniumchloridlösung` and `Natriumacetatlösung` their concentration limits, and the structural preview stays with the existing catalog keys.

These are the first dosed salts whose own ions are the weak electrolytes rather than a hydrolysing cation from the hydroxide table. Ammonium joins the existing ammonia family (pKa 9.25) and acetate the existing acetic-acid family (pKa 4.75), so the pH comes out of the shared speciation without a new equilibrium: 0.1 mol/L ammonium chloride reads pH 5.13 and sodium acetate pH 8.88, from the dry salt exactly as from the stock. Above saturation each salt keeps its reservoir at the tabulated limit, conserves both ions and redissolves on dilution, which exercises the same `registerSolidSalt` path as the other pairs. Neutralisation also runs through the shared model: sodium acetate with hydrochloric acid buffers at 4.75, ammonium chloride with sodium hydroxide at 9.25.

The table has to spell its ions the way Kekulé writes them. Ammonium is `[N+]` in `chemlib/saltSolubility.ts`, and `[NH4+]` is only an alias of the acid family; with the alias in the row, both `registerSolidSalt` and the settling loop miss, the salt dissolves completely instead of settling, and a saturated charge reads 6.6 mol/L NH₄⁺ at pH 4.2 with no solid at all. `tests/salt-ammonium-acetate.test.ts` therefore compares the fragment list against the table before it doses anything, and then covers the catalog phase and density, dissolution stoichiometry, stock parity, the two documented pH values, the saturated reservoir with its dilution step and the two neutralisations.

Remaining salt gaps stay documented rather than filled by guesswork. The sulfate references `Calciumsulfat-Dihydrat`, `Kupfer(II)-sulfat-Pentahydrat` and `Eisen(II)-sulfat-Heptahydrat` keep only their stocks because a dry recipe would need a decided hydrate, and ammonium sulfate, potassium thiocyanate, potassium permanganate, potassium sodium tartrate, magnesium sulfate heptahydrate, sodium thiosulfate pentahydrate, iron(II) sulfide, silver chloride, barium sulfate and calcium carbonate stay reference-only until their recipe data is stored next to the salt equilibria. The [coverage report](structure-library-coverage.md) lists the 36 dosed salt entries, the 17 paired identities, the 2 stock-only identities, and the 11 reference-only identities.

### Implemented example: salts with more than one ion of a kind

Seven further salt identities now carry a dry solid and a stock: `Silbernitrat` with `Silbernitratlösung`, `Bariumchlorid` with `Bariumchloridlösung`, `Calciumchlorid` with `Calciumchloridlösung`, `Eisen(III)-chlorid` with `Eisen(III)-chloridlösung`, `Natriumcarbonat` with `Natriumcarbonatlösung`, `Natriumsulfat` with `Natriumsulfatlösung`, and `Zinksulfat` with `Zinksulfatlösung`. Every pair already had its stock and its tabulated saturation and solid density in `chemlib/saltSolubility.ts` (8.80, 1.38, 5.04, 2.69, 2.01, 1.30 and 1.79 mol/L; 4.35, 3.86, 2.15, 2.90, 2.54, 2.66 and 3.54 g/mL), so the missing half was the formula unit of the solid. `Calciumchlorid` had been a reference-only entry until now and becomes the dosed solid.

These are the first catalog solids whose formula unit carries more than one ion of a kind, which changes how the graph is written. `Molecule.addBond` moves exactly one electron per ionic bond toward the more electronegative atom, so a salt needs one ionic bond per anion: `BaCl₂`, `CaCl₂` and `FeCl₃` give their two or three chlorides one electron each and serialise as `[Ba2+]`, `[Ca2+]` and `[Fe3+]` next to the matching number of `[Cl-]`, exactly the entries of the table. The oxyanion salts take the other route: the sulfate and carbonate skeletons stay neutral and the two alkali metals or the zinc atom transfer one electron per bond to the two unprotonated oxygens, so the fragment comes out as `[O-]S(=O)(=O)[O-]` or `[O-]C(=O)[O-]` and `[Na+] ×2` or `[Zn2+]`. `Silbernitrat` reuses the pre-computed `charges` of `Kaliumnitrat`, because four-bonded nitrogen cannot be neutral in the first place. A wrong bond count is silent: `registerSolidSalt` falls through to `sDissolveSalt`, so the dry salt would dissolve completely and never hold a reservoir, which is why `tests/salt-solids.test.ts` compares the fragment list against the table before it doses anything.

The chemistry stays inside the existing equilibrium models. The hydrolysing cations carry the pH of their stocks: 0.1 mol/L `Eisen(III)-chlorid` reads pH 1.64, `Zinksulfat` 5.52 and `Silbernitrat` 6.48 from the silver hydrolysis family, while sodium carbonate reads 11.66 as a base and sodium sulfate 7.52 from the hydrogen sulfate step; `Calciumchlorid` and `Bariumchlorid` stay close to neutral at pH 6.73 and 6.93. Dosing 0.1 mol of the dry salt into 100 mL water therefore yields the same pH, the same stored ions and the same volume as the corresponding stock. Above saturation the solid keeps a reservoir at the tabulated limit and redissolves on dilution; `Eisen(III)-chlorid` settles at an analytical 2.72 mol/L instead of 2.69, because the solubility product reads the free Fe³⁺ that hydrolysis lowers. The new solids join the existing interactions unchanged: `Silbernitrat` shows the chloride with `Natriumchloridlösung` as AgCl, `Bariumchlorid` precipitates BaSO₄ from `Natriumsulfatlösung`, and `Natriumcarbonat` releases the same CO₂ as its stock when dosed into hydrochloric acid.

`tests/salt-solids.test.ts` covers all seven pairs: catalog phase, density and concentration limit against the table, the fragment list against the table ions, complete dissolution to the right stoichiometry at 0.1 mol/L, agreement with the same amount of stock in pH and ion amounts, the documented pH of the five solids that move the water equilibrium, a saturated reservoir that conserves both ions and redistributes on dilution, and the three interaction cases above. None of the seven solids has a builder structure yet, so they extend ChemLab's solid selection ahead of the structures library. The builder catalog lists only entries that resolve to a structure or to the constituents of a mixture, so these salts do not appear there as rows that cannot load, and the [coverage report](structure-library-coverage.md) keeps them in its "entries without a builder structure" list until a crystal or molecule definition exists for them.

### Planned extension to all selectable compounds

Implement this as a shared identification, enrichment and admission pipeline for the catalog and manually edited compounds, not as automatic dosing from CIF coordinates:

1. Inventory every compound selectable in Molecule Builder and join it to its stable catalog identity, including molecular structures and every listed crystal. Include hydrates, network solids and partially occupied structures; audit selectable elemental and representative-material entries alongside compounds. Record supported phases and specific gaps such as missing chemical data, recipes or simulation models. Reference-only behaviour is an interim gap, not the completion criterion for a selectable compound.
2. Maintain a separate validated analytical definition: formula-unit stoichiometry, hydrate water, complete polyatomic-ion graphs, formal charges and protonation steps. Check mass and charge balance. Preserve source omissions (especially hydrogen and occupancy) as structural provenance; do not infer missing chemistry silently from site counts, ion labels or a display formula.
3. Fetch and retain source-backed compound identity and phase-specific data during enrichment: density, solubility or Ksp with temperature and units, and relevant aqueous dissociation data. Resolve conflicting identities and measurements explicitly. PubChem molecular identity alone does not establish a crystal phase, hydrate, solubility or simulation compatibility.
4. Check compatibility with existing equilibrium, complexation, redox and gas families before admitting a dose. Reuse registered families rather than creating duplicate acid/base systems from fetched salt pKa values. Implement missing models where needed to meet the catalog-wide requirement. While unresolved, retain a specific reason and track the compound as incomplete; do not fabricate chemical behaviour to enable a dosing button.
5. For every listed or successfully identified manually altered salt, implement separate solid and aqueous recipes linked to one compound identity, including solid reservoirs, dissolution and solution concentration limits. For other compounds, supply the chemically appropriate dosing phase or phases. Label the chosen phase and keep handoff consistent with the selected representation. Preserve existing catalog identities and saved data where possible, exact structural validation and reagent permissions. Reject stale original-recipe matches for edited chemistry and route those structures through re-identification; a matching name or formula is insufficient authorization.
6. Verify each selectable compound with representation-to-reagent handoff, formula/charge/mass conservation, appropriate phase behaviour and save/restore. For salts, test both solid and solution paths, dissolution, saturation, dilution, relevant pH/precipitation/gas behaviour, and agreement between the two forms after dissolution. Include compatibility cases involving existing reagents. Maintain a coverage report of all selectable compounds and both salt forms, with remaining gaps clearly identified; completion requires direct ChemLab compatibility for the full selectable compound catalog.
7. Test manual inorganic edits end to end: fresh identification and data retrieval, invalidation of stale asynchronous lookup results, correct solid/solution recipes, measured-data provenance, solubility and coupled equilibria, reagent interactions and save/restore. Include inorganic molecules, salts with polyatomic ions, changed protonation and stoichiometry, hydrates, invalid/incomplete structures and lookup failures. Compare the custom-compound result against the corresponding validated catalog reagent where available, and verify that layout-only edits do not change chemical identity.

`tests/bicarbonate.test.ts` supplies the first regression case: unchanged and edited crystal matching, phase-specific handoff, aqueous preview, dry-salt mass and charge, dissolution and saturation reservoirs, dilution, dry and wet save/restore, pH and sodium stoichiometry, interconversion with carbonate through one acid/base equivalent, and consistent CO₂ release. The NaHCO₃ solubility entry uses the actual fragment SMILES `[O-]C(O)=O` so solid registration and aqueous speciation use the same ion identity.

Step 1 and the coverage part of step 6 run against the live modules: [ChemLab structure coverage](structure-library-coverage.md) lists every selectable compound with its dose, every salt identity with its solid recipe, aqueous stock and reference-only forms, and the remaining gaps. It is generated by `scripts/generate-structure-coverage.ts` from `data/chemicals.ts`, `molecule-builder/catalog.ts` and `chemlib/saltSolubility.ts`; `tests/structure-coverage.test.ts` fails when the tracked report or its JSON falls behind the catalog. The table joins a solid and a stock by the catalog formula without hydrate water, so a pentahydrate reference belongs to the same analytical compound as its anhydrous stock.

- The CIF converter applies the reported symmetry and retains measured coordinates, including partial site occupancies. When a measurement provided no hydrogen positions, the crystal view says so. - Crystal colours group sites by their curated ion formula. The rules in `crystalIons` use element membership and, for hydrates, short periodic neighbour distances to distinguish polyatomic ions from neutral water. These labels are display metadata and leave imported formal charges and the simulation recipes intact. [Neutron diffraction dataset for copper sulfate pentahydrate](https://www.crystallography.net/cod/9008253.html)

- For editor graphs, **Fit geometry** uses the local VSEPR layout for supported acyclic structures. A deterministic distance-constraint fallback uses approximate bond lengths, angles, and nonbonded separation for rings and unsupported coordination. A calculated ring uses one plausible geometry. Energies, conformational populations, and stereochemical preferences are outside this estimator.
- **Valence electrons** in 3D draws dots for the bonding electrons in the graph and the nonbonding electrons assigned by a main-group Lewis count. Translucent ellipsoids show the approximate regions they occupy. Transition-metal nonbonding shells, delocalized electron density, and quantum orbitals are outside this model.
- The 2D molecular view draws Lewis bonds and nonbonding electrons from the editable graph. Atom labels use the Allen-scale ionic approximation on the drawn bond orders plus stored formal charges. The notation distinguishes formal charge from oxidation state and marks undetermined comparisons with a question mark. Resonance, coordination, and unusual valence can need additional chemical context. The stored dative bonds in the silver–ammonia example use donor-pair bookkeeping. [IUPAC oxidation-state recommendation](https://iupac.org/recommendation/comprehensive-definition-of-oxidation-state/)
- The nine catalog polymers have curated atom membership and two continuation sites for the constitutional repeating unit. Editing a polymer reference starts with a copy of the repeat unit, with the valence of both continuation bonds reserved. [IUPAC graphic representations of macromolecules](https://doi.org/10.1351/pac199466122469)
- The crystal formula view uses catalog formulae for unchanged references and site occupancies for edited compositions. Curated ion formulas supply the charge labels, including polyatomic ions. A new ion is added as a charged site at a free fractional position, which remains editable. A changed composition updates the formula and 3D model immediately.
- The aqueous overview groups the distinct species of the supported electrolyte stocks in one view. It illustrates the catalog solute ions or representative acid–base products. The drawings convey identity and charge. Species proportions and equilibrium are calculated by ChemLab for the actual vessel. The optional hydration illustrations depict water molecules and separate hydrogen bonding from ion–dipole contacts. The waters and contacts are display elements outside the saved structure. [X-ray and simulation study of aqueous NaCl](https://pubs.rsc.org/en/content/articlehtml/2022/cp/d2cp00162d)
- When an editable Lewis drawing crowds labels or bonds, the builder searches projections of its fitted 3D geometry for more room. This also repairs crowded saved drafts, retaining atom IDs, bond orders, and coordinates of their existing 3D model.

## Orbital view

The 3D molecule model selector offers one orbital at a time so the phase and nodal shapes stay legible. Blue and orange are opposite signs of the wavefunction. Either sign convention describes the same orbital; neither color denotes an electric charge or an electron population.

Ten catalog specimens have offline Kohn–Sham orbital surfaces computed with PBE0/def2-SVP at their displayed nuclear geometry, including H₂, O₂, N₂, H₂O, CH₄, NH₃, ethene, ethyne, CO₂ and formaldehyde. The generator samples at 0.22 Å and draws the two signed surfaces at |ψ| = 0.045 bohr⁻³ᐟ². O₂ uses spin-polarized triplet calculations and offers both singly occupied α orbitals. Degenerate orbital shapes depend on the chosen basis within the degenerate subspace. Virtual orbital shapes depend on the finite basis set. [PySCF](https://doi.org/10.1063/5.0006074) · [PBE0](https://doi.org/10.1063/1.478522) · [def2 basis](https://doi.org/10.1039/B508541A)

Other molecules and edited geometries offer a labeled local valence-bond illustration of supported σ bonds, π bonds and lone pairs. Its orientation follows the geometry, and coplanar π overlap shows two opposite phases. The fallback describes local bonding and does not calculate energies, delocalized states, transition-metal orbital populations, or unsupported coordination. Odd-electron graphs and neutral O₂ without matching reference coordinates bypass the closed-shell fallback. Two-dimensional structures, lattice views and whole-solution previews do not expose the molecule model selector. [Valence bond theory](https://openstax.org/books/chemistry-2e/pages/8-1-valence-bond-theory) · [Multiple bonds](https://openstax.org/books/chemistry-2e/pages/8-3-multiple-bonds)

## Individual atoms

The builder defaults to the **Shells** view for a single atom. This Bohr-style schematic draws moving electron dots on circular rings with illustrative periods of 28–76 seconds. The selected shell and its tag are colored, and the others are gray. The rings stay in the plane of the screen while dragging rotates the nucleus. The teacher can pause the animation in either widget with the WebWriter option **Pause electron motion in the shell model**. The viewer respects reduced-motion preferences. The periodic-table preview opens an enlarged detail card with the same viewer. A builder on the same worksheet can open the element and model from that preview.

The shell model shows one sphere per proton and neutron for a named reference isotope. For 84 elements, the mass number comes from the row with the highest representative isotopic composition in the NIST table. For the other 34, it comes from the longest-lived isotope in the existing periodic-table nuclide extract. The placement and size of the individual spheres are schematic. [NIST isotope data](https://physics.nist.gov/cgi-bin/Compositions/stand_alone.pl?ascii=ascii2&ele=&isotype=all) · [Nuclide extract provenance](../data/periodic-table/sources.json)

The configuration is the isolated ground state from the periodic table data. A bonded atom or an atom that belongs to a polyatomic lattice ion shows the neutral element as a reference. Supported monatomic ions use the isolated ion’s configuration or, for oxide and sulfide, a labeled formal closed-shell model. Unverified ionic configurations are unavailable. The predicted label follows the neutral configuration source. [NIST neutral configurations](https://www.nist.gov/pml/ground-levels-and-ionization-energies-neutral-atoms) · [NIST Atomic Spectra Database](https://www.nist.gov/pml/atomic-spectra-database)

**Orbitals** shows the subshells after the noble-gas core initially and preserves the order of the source configuration. For ions whose shorthand is a noble-gas core by itself, the outermost populated shell is shown. The left-facing control reveals the core. Hovering a surface names its real orbital and occupancy. Empty orbitals are faint. The teaching diagram assigns equivalent orientations in a fixed order and fills them singly before pairing. The hydrogen-like shapes show the outer radial region at 20% of its peak amplitude. The overlay uses a compressed relative size range for multielectron atoms. A physical ångström ruler is used only for one-electron states in the builder. Without WebGL, the same shell counts are drawn in SVG and the orbitals appear as labeled cross-sections. [NIST DLMF hydrogenic solutions](https://dlmf.nist.gov/18.39)

The 3D overview uses translucent gray, with smaller subshells and core orbitals fainter. The opacity also accounts for how many orientations overlap. A click on a configuration tag isolates that subshell in phase colors. Clicking the tag again returns to the overview. Hovering still names and colors one orbital. Core orbitals are generated when first revealed and reused for the current atom.

The nucleus uses the single-proton CODATA charge radius or the approximate spherical radius of 1.2 fm times the cube root of the mass number. The model uses ångströms directly for one-electron ions and atoms. For multielectron species, it converts the nuclear radius to the normalized orbital scene using the neutral atom’s empirical radius or the existing radius fallback. The nucleus is normally smaller than a pixel. [CODATA proton radius](https://physics.nist.gov/cgi-bin/cuu/Value?rp) · [Texas A&M nuclear radius approximation](https://sibor.physics.tamu.edu/wp-content/uploads/sites/15/2021/04/lecture13-chapter12_new.pdf)

## Regenerating the checked-in data

Use Python with ASE 3.26.0, Gemmi 0.7.3, and RDKit 2025.3.5. `data/structures/sources.json` identifies the records, molecular connectivity, hand-curated representations, and the coverage set. The generated snapshots are shipped with the widgets and require no runtime network access.

1. Put PubChem's computed conformer SDFs in `CACHE/pubchem/<CID>.sdf`. The endpoint is `/rest/pug/compound/cid/<CID>/SDF?record_type=3d`. Save a record only if the request succeeds. Missing records fall back to a local estimate.
2. Query COD with the comma-separated archive IDs from `crystals` and `metalCifs`, using `format=zip`. Save the CIF archive in `CACHE/cod-selected.zip`. [COD REST query formats](https://wiki.crystallography.net/RESTful_API/)
3. Run `python scripts/generate-structure-library.py CACHE`. Inspect the generated changes and run `tests/molecule-builder.test.ts` using the repository test command. The suite validates coverage, site coordinates and occupancies, example geometries, and dose matching.

4. With PySCF 2.11.0 and scikit-image 0.25.2, run `OPENBLAS_NUM_THREADS=1 python scripts/generate-reference-orbitals.py` after changing a reference geometry. The packed, indexed meshes retain their absolute coordinates and are decoded only when displayed.
